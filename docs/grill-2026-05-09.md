## Confirmed against UiPath docs

1. **Maestro is BPMN 2.0 + UiPath extensions, with User Task / Service Task / Script Task / Business Rule Task all executable.**
   Source: <https://docs.uipath.com/maestro/automation-cloud/latest/user-guide/tasks-in-bpmn-modeling>.
   AURORA's `process.bpmn` uses these correctly.

2. **Maestro instance pause / resume / retry / cancel / move / migrate exist as runtime operations.**
   Source: <https://docs.uipath.com/maestro/automation-cloud/latest/user-guide/process-overview-homepage>.
   The doc describes them as actions on a live instance via the Orchestrator UI; Python-SDK exposure to be confirmed at integration time (`uipath-python` 2.10).

3. **Action Center Form Tasks: create via `UiPath.Persistence.Activities.FormTask.CreateFormTask` (XAML) or Orchestrator OData `/odata/Tasks/...` endpoints. Catalog must pre-exist (error code 2451 if missing).**
   Sources: <https://docs.uipath.com/action-center/standalone/2023.10/user-guide/create-form-task> ; <https://docs.uipath.com/orchestrator/standalone/2024.10/api-guide/tasks-requests>.
   Folder context required via `X-UIPATH-OrganizationUnitId` (or `X-Uipath-Organizationunitid`) HTTP header — confirmed at <https://docs.uipath.com/orchestrator/automation-cloud/latest/api-GuidE/building-api-requests>.
   **Implication:** Concierge must ensure the `aurora_supply_chain_approvals` catalog exists before any form task creation, and must set the folder header on every call.

4. **Coded Agents support LangGraph, LlamaIndex, OpenAI Agents SDK, Google ADK, PydanticAI, Microsoft Agent Framework.** Repo `UiPath/uipath-langchain-python` ships the `uipath` CLI with `uipath init`, `uipath pack`, `uipath publish`.
   Sources: <https://docs.uipath.com/agents/automation-cloud/latest/user-guide/about-coded-agents> ; <https://github.com/UiPath/uipath-langchain-python> ; <https://www.uipath.com/community-blog/tutorials/build-a-uipath-coded-agent-without-leaving-your-ide>.
   **Implication:** AURORA's MaintainerHealth agent on `openai-agents` framework is supported. Manifest is `uipath.json`, generated by `uipath init`, alongside `langgraph.json` (or per-framework equivalent), `pyproject.toml`, and `entry-points.json`.

5. **Studio Web publish for agentic processes is button-driven from the Studio Web canvas; deploy is from Orchestrator.**
   Source: <https://docs.uipath.com/maestro/automation-cloud/latest/user-guide/publishing-deploying-and-upgrading-agentic-processes> ; <https://docs.uipath.com/studio-web/automation-cloud/latest/user-guide/publishing-a-project>.

6. **Test Manager flow: write tests in Studio → publish project (.nupkg) to Orchestrator → link automation in Test Manager. The Test Manager API is read/sync-oriented, not write-oriented.**
   Sources: <https://docs.uipath.com/test-manager/automation-cloud/latest/user-guide/test-manager-api-overview> ; <https://docs.uipath.com/test-manager/automation-cloud/latest/user-guide/automate-test-cases> ; <https://docs.uipath.com/test-manager/automation-cloud/latest/user-guide/creating-automated-tests>.

## Contradicted by UiPath docs

1. **`<bpmn:receiveTask id="WaitForCI">` with `<uipath:messageEventDefinition>` is not executable in Maestro.**
   `examples/oss-supply-chain-defender/process.bpmn:273` uses Receive Task. Maestro's task-types reference table marks Receive Task as ✅ modeling / ❌ execution.
   Source: <https://docs.uipath.com/maestro/automation-cloud/latest/user-guide/tasks-in-bpmn-modeling>.
   *However*, the advanced-patterns doc (<https://docs.uipath.com/maestro/automation-cloud/latest/user-guide/advanced>) describes "wait for a specific message with a deadline" using a Receive Task with a boundary timer. Treat as contradicted until clarified.
   **Resolution (D2):** Primary path — Send Task + intermediate message catch event with a boundary timer. Fallback — User Task auto-completed by webhook via `POST /odata/Tasks/.../Complete`.

2. **AURORA's `<uipath:taskBinding kind="coded-workflow|coded-agent|action-center-form|rpa-package">` schema is not a documented Studio Web / Maestro extension.**
   The official agentic-process toolchain stores bindings in JSON files at the project root: `bindings.json`, `entry-points.json`, `langgraph.json`, `uipath.json`, generated by `uipath init`. UiPath docs nowhere describe an inline `<uipath:taskBinding>` BPMN extension element. A `process.bpmn` file with these elements is *not importable* into Studio Web.
   Source: <https://docs.uipath.com/studio-web/automation-cloud/latest/user-guide/configuring-agentic-process-elements> ; <https://github.com/UiPath/uipath-langchain-python> (project layout).
   **Resolution (D1):** Strip `<uipath:taskBinding>` from `process.bpmn`. `bindings.json` (already present) is the only source of truth. Re-run `uipath init` per agent/coded-workflow to regenerate manifests.

3. **No public `uip publish` CLI exists for Maestro/agentic processes; only Coded Agents/Coded Workflows have CLI publish.**
   The official CLI from `uipath-python` is `uipath` (not `uip`). `uipath publish` ships the most-recently-packed Coded Agent / Coded Workflow `.nupkg` to Orchestrator. There is no documented CLI verb that publishes a Studio Web Maestro project.
   Source: <https://github.com/UiPath/uipath-langchain-python> (CLI reference).
   **Resolution (D3 + CLI rename):** rename `uip` → `uipath` across the codebase. For Maestro publish: build a small Python wrapper that captures Studio Web's HTTP publish call (via Playwright + `browser_network_requests`) and replays it headlessly. Keep a Playwright-UI fallback warm.

4. **`uipath.json` is generated by `uipath init` — not hand-authored.**
   The hand-written `uipath.json` at `examples/.../agents/vuln-lookup/uipath.json` (with model.tier and credentials.scope fields) is not the schema `uipath init` writes — that file likely won't validate.
   Source: <https://medium.com/@jagtapabhi13/building-langgraph-powered-ai-agents-in-uipath-with-uipath-python-sdk-32030c7c77c4>.
   **Resolution:** Regenerate by running `uipath init` inside each agent/coded-workflow dir, then layer in AURORA additions only where the schema permits.

5. **Test Manager has no documented "publish a generated test set via API" endpoint.**
   The Tester agent's claim that it "writes Test Manager test cases and publishes them" cannot be done end-to-end via the Test Manager API alone. The supported flow is: Tester writes test workflows in Studio → `uipath publish` to Orchestrator → Test Manager picks them up via the Select Automation UI / API.
   **Resolution:** Tester emits Studio test packages and `uipath publish`es them. The Test Manager linkage step is either UI-driven (Playwright fallback) or done via a small reverse-engineered call after the package lands in Orchestrator.
